# 雀録 — 麻雀スコア Ver.1

4人麻雀の点数と累計収支を、ブラウザだけで記録するアプリです。
HTML・CSS・JavaScriptで作成し、追加ライブラリやデータベースは使っていません。

公開版: https://janroku-score-kouka.hd76xfvnrf.chatgpt.site/

## 起動方法

Node.jsがインストールされた環境で、このフォルダーをターミナルで開きます。

```powershell
npm start
```

ブラウザで http://127.0.0.1:4173 を開いてください。終了するときはターミナルで Ctrl+C を押します。
依存パッケージはないため、npm install は不要です。
index.html の直接ダブルクリックではなく、上の方法で起動してください。

## 使い方

1. 4人の名前を入力して開始します（1人20文字まで）。
   一度使った名前は端末内の一覧に残り、次回からタップして入力できます。新しい名前はそのまま手入力できます。
2. 対局終了時に3人分の収支を入力し、どれか1人を空欄にします。
3. 「結果を登録」を押すと、4人の収支合計が0になるよう空欄を自動計算し、履歴と累計を更新します。
4. 次の対局も同じように登録します。名前の順番はゲーム中変わりません。
5. 「ゲームをリセット」で確認画面を開き、「リセットする」で保存内容を初期化します。
6. 最後に「この対局結果を保存」を押すと、リセット後も「保存した対局」で最終結果を確認できます。

## iPhoneのホーム画面に保存

公開URLをSafariで開き、画面下の共有ボタンから「ホーム画面に追加」→「追加」を選びます。
ホーム画面に「雀録」のアイコンが作られ、次回からアイコンをタップするだけで起動できます。
iPhoneで通常のブラウザ表示を開いた場合は、この手順を画面上にも表示します。ホーム画面から起動した場合、案内は表示されません。

アプリ表示用のWeb App Manifest、Apple Touch Icon、Service Workerを含みます。一度読み込んだ後は、通信できない場合でもアプリ画面を起動できます。対局データは引き続き、そのiPhoneのブラウザ内に保存されます。

20,000点負けは「-20」、10,000点勝ちは「10」と入力します。
マイナスと小数1桁まで対応。「±」ボタンでも正負を切り替えられます。
4人全員を入力した場合も登録せず、1人を空欄にする案内を表示します。
桁の誤入力を防ぐため、入力値と自動計算値は −99,999.9〜99,999.9 に制限しています。

## 計算と保存の仕組み

- 残り1人の収支 = 0 − 入力された3人の収支合計。
- 各プレイヤーの収支をそのまま合計して累計を表示。
- 履歴の最下段に、各回の収支を足した「現在累計」を表示。
- 結果登録後は追加された最新行へ移動し、その行を薄い黄色で強調表示。
- 各プレイヤーのチップ枚数を入力すると、1枚5点で換算して「最終合計」を表示。チップも自動保存。
- よく使うプレイヤー名と保存済み対局は、進行中ゲームとは別にLocalStorageへ保存。ゲームをリセットしても残ります。
- 自分より累計が大きい人数 + 1 が順位。同点は同順位です。
- 小数の丸め誤差を防ぐため、内部では表示値を10倍した整数で扱います。画面の30は内部で300です。
- 名前・履歴・累計を `janroku.game.v1` というキーでLocalStorageに保存します。旧形式の履歴は自動変換します。
- 読み込み時は履歴から累計を再計算し、整合性を保ちます。
- 保存成功後に画面を更新するため、保存失敗時には入力内容が残ります。
- 保存データが壊れていた場合は案内を表示し、新規開始時に上書きを確認します。

保存は同じ端末・同じブラウザ・同じURL内で有効です。通常はブラウザを閉じても残りますが、ブラウザのサイトデータを削除すると消えます。端末間の同期は行いません。ローカル版と公開版の保存領域も別です。1つのタブで利用してください。

## 動作確認

```powershell
npm test
```

計算・名前・不正入力・保存・チップ精算・プレイヤー一覧・終了結果保存を検証する8つの自動テストが成功しています。
実ブラウザ（Edgeの自動テスト）でも以下を確認しました。

- 4人の登録、3人の入力、空欄1人の自動計算、空欄の4つの位置
- 負数の入力、負数の自動計算、小数1桁
- 履歴追加、各回の収支、累計、順位と同順位
- ページ再読み込み後の復元
- リセットのキャンセルと実行、リセット後の再読み込み
- 全空欄、複数空欄、4人入力、不正文字の拒否
- 保存失敗時に入力が残り、未保存の結果が登録されないこと
- 320・375・390・430・768・1280px幅で横にはみ出さないこと
- スマホ・PCのスクリーンショットによる表示確認

ブラウザエラーは発生していません。スマホはブラウザの画面幅で確認しており、実機での確認は未実施です。

対応ブラウザ向けにWebMCPの結果登録口も用意しています。通常の画面操作には不要です。対応する実行環境が利用できなかったため、この連携部分の動作確認は未実施です。

## 今後の拡張

計算をscoring.mjs、保存をstorage.mjs、表示をapp.mjsに分けているため、結果の編集・取り消し、CSV出力、複数ゲームの保存などを段階的に追加できます。ウマ・オカを加える場合は、まずscoring.mjsにルールを追加し、計算テストを書いてから画面につなぐと理解しやすくなります。
